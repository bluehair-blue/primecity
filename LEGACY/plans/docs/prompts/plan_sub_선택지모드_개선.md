## 0. 설계 원칙

| 원칙 | 설명 |
|---|---|
| **코드블록 = 시각적 격벽** | AI가 실수로 한 줄로 이어 붙이지 못하도록 ``` ``` 래핑으로 강제. 상태창(STATUS)과 동일한 구조 사용 |
| **선택지는 분기, 사소함은 X** | 서사 방향이 갈라지는 갈림길에만 사용. 일상적 선택("차 마시기 vs 물 마시기")은 제외 |
| **유저 페르소나 반영** | {{user}}는 대개 프로듀서·제작자 포지션 — 말 한마디가 커리어를 흔드는 역할. 선택지 어휘도 그에 맞춰야 함 |
| **재미 = 결과의 상이성** | 세 선택지가 각기 다른 결과·감정·관계 변화로 이어져야 함. "안전/도전/관찰" 같은 일변도 금지 |
| **작위성 배제** | rules.user_agency(메인 프롬프트)와 동일 — 메타적 직접 질문은 선택지 외 본문에 등장하지 않음 |

## 1. 현재 문제 진단

### 문제 1: AI가 줄바꿈을 안 함

**현재 구조**:
```json
"template_literal": "📋 다음 행동:\n\n① ...\n② ...\n③ ...\n\n(자유 입력도 가능합니다.)"
```

- JSON `\n` 이스케이프를 AI가 literal 텍스트로 복제할 때 실제 줄바꿈으로 렌더링 못하는 경우 다발
- 경량 모델이 "한 줄에 이어 붙이면 안 된다"는 `forbidden_patterns` 지침을 읽어도, template 자체가 보조적 역할이라 실패 빈번

### 문제 2: 선택지 퀄리티 부족

현재 `rules` 5개는 대부분 "서사에 맞게, 갈림길에만" 수준의 일반론.
- 유저 페르소나(프로듀서) 특화 X
- "매력적 선택지"의 구체 기준 없음 → AI가 "A에게 다가간다 / B에게 말한다 / C 지켜본다" 같은 건조한 삼박자 반복

### 문제 3: 배치 모호성

현재: 그저 "선택지 블록 출력" — 상태창 앞인지 뒤인지 미명시.
사용자 요구: **상태창 "위"**에 별도 코드블록.

## 2. 개선안 A — 코드블록 래핑

### 새 출력 포맷

````
```CHOICE
📋 다음 행동

① (선택지 A — 서사 방향 + 유저 행동/대사)
② (선택지 B — 다른 방향)
③ (선택지 C — 또 다른 방향)

(자유 입력도 가능합니다.)
```
````

**효과**:
- `CHOICE` 언어 태그로 AI가 "이건 구조적 코드블록"임을 인지 → 내부 줄바꿈 보존 확률 급등
- 상태창 `STATUS` 블록과 시각 일관성 확보
- 한 줄 이어 붙이기 물리적 불가능

### 배치 순서 (response_order와 정합)

메인 프롬프트 `out.response_order`: `1. 장면 서술 → 2. 상태창 → 3. 입력 유도`
→ 선택지는 **"2. 상태창 직전"**에 출력 (서사 직후, 상태창 위)

## 3. 개선안 B — 선택지 품질 기준

### 3-1. 3개 축 원칙 (다양성 강제)

세 선택지는 반드시 **서로 다른 축**에 배치:

| 축 | 예시 (오디션 심사 현장) |
|---|---|
| **행동** — 직접 개입 | ① 진시혁의 혹평을 반박한다 |
| **관계** — 유대 형성 | ② 탈락한 장그루를 따라가 한마디 건넨다 |
| **관찰** — 정보 수집 | ③ 나하린이 누구를 주시하는지 조용히 지켜본다 |

→ "안전/도전/관찰" 일변도가 아닌, **서사 결과의 결이 다른** 3개 축

### 3-2. 페르소나 가이드 (프로듀서 보정)

선택지 어휘는 **직업적 위치에 맞춰야 함**:

❌ 약한 예: "친구처럼 응원한다"
✅ 강한 예: "프로듀서 권한으로 재평가를 요청한다"

❌ 약한 예: "조용히 듣는다"
✅ 강한 예: "심사평은 접어두고, 녹음실 키를 건넨다"

→ {{user}}의 "결정권·위치·권한"이 드러나는 행동 어휘 우선.

### 3-3. 매력 요소 (재미 장치)

각 선택지에 최소 1개 포함:
- **관계 레버리지**: 특정 캐릭터 호감도 ±, 기존 관계에 파장
- **서사 분기**: 장면·씬의 분기가 분명히 보임
- **감정 긴장**: 불편함·유혹·배신감·호기심 등 감정 단어 함의
- **말맛**: 유저가 소리 내어 읽었을 때 재미있는 표현 (리듬·반전·구체명사)

❌ 무맛 예: "선택을 한다"
✅ 맛있는 예: "진시혁이 아직 안 본 무대 영상 한 컷을 펼쳐놓는다"

### 3-4. 길이 가이드

- 한 선택지 = **한 줄**, 최대 ~25자 전후
- 너무 짧으면(< 10자) 맥락 부족, 너무 길면(> 35자) 덩어리
- 첫 단어에 **동사** 배치 (유저 행동이 이미지로 떠오르도록)

## 4. 개선안 C — 타이밍 규칙

### 언제 출력하는가

| 상황 | 선택지 출력 |
|---|---|
| 서사가 뚜렷한 갈림길에 도달 | ✅ 제공 |
| 씬 초반·환경 묘사 중 | ❌ 금지 (대화의 흐름 깨짐) |
| 이미 유저가 명확한 의도를 표현한 직후 | ❌ 금지 (결정권 침범) |
| 유저가 "막막하다"는 신호를 보낼 때 (대사 짧음·연달아 생략) | ✅ 제공 |
| 서사 전환점(라운드 변경·시간 점프·새 캐릭 등장) 직후 | ✅ 적극 제공 |

### 빈도

- **매 턴 금지**: 선택지가 습관이 되면 서사 몰입 파괴
- **2~4턴에 1회 권장**: 자연스러운 호흡

## 6. 비교: 개선 전 vs 후 (같은 장면)

**장면**: 1R 등급 평가 도중, 장그루 무대 직후 진시혁이 "재도전? 본인이 더 잘 알 텐데요"라고 혹평을 날림.

### 개선 전 (현재 AI가 낼 법한 선택지)

```
📋 다음 행동: ① 장그루에게 다가가 격려한다 ② 진시혁에게 반론한다 ③ 아무 말 없이 메모를 적으며 지켜본다
```

- 한 줄에 이어 붙음
- "격려/반론/지켜본다" — 평범한 3축
- 프로듀서다움 없음

### 개선 후

````
```CHOICE
📋 다음 행동

① "그 혹평, 심사평에 넣으시겠어요?" 진시혁에게 공개 맞선다
② 장그루를 따라 복도로 나가 명함부터 건넨다
③ 나하린이 장그루를 언제 체크했는지 기록을 되짚는다

(자유 입력도 가능합니다.)
```
````

- 코드블록 래핑으로 줄바꿈 확정
- ① 직접 행동(공개 vs 심사평) / ② 관계 유대(바로 스카우트) / ③ 관찰(나하린의 관심사 추적) — 3축 분리
- "공개 맞선다", "명함 건넨다", "기록 되짚는다" — 프로듀서 권한 어휘
- 말맛 있고 각기 다른 결과로 이어짐

## 8. 연쇄 영향

| 다른 로어북 | 영향 | 대응 |
|---|---|---|
| 메인 프롬프트 `out.response_order` | 선택지는 "상태창 직전"에 삽입됨 — 기존 순서와 호환 | 무변경 (선택지가 추가 레이어로 끼어듦) |
| 오디션 로어북들 | 선택지 모드 활성 시 오디션 라운드 상황에 맞는 선택지 제공 | 무변경 (본체 로어북이 스스로 감지) |
| 기타 모드 | 각 모드 상황에서 선택지 자동 반영 | 무변경 |

## 9. 리스크 및 롤백

- **리스크**: 코드블록 래핑을 AI가 오히려 "실행 가능한 코드"로 오인해 실행하려 할 가능성 → `CHOICE` 태그는 커스텀이라 실행 언어 아님, 안전
- **롤백**: 단일 파일 수정 → `git revert` 즉시 가능
