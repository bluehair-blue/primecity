## 구획 A — 프롬프트 구조 원칙

---

### 1. 배치 순서 = 우선순위 계층

프롬프트 상단에 위치할수록 AI가 강하게 따른다. 배치 순서 자체가 지시의 가중치.

```
◇절대규칙   ← 어떤 상황에서도 어기면 안 되는 것
◇규칙       ← AI 역할, 시점, 톤, 금지사항
◇출력지침   ← 출력 형식, 대사 양식, 묘사 비율
◇이미지규칙 ← 이미지 출력 공식, 상황 넘버
◇상태창     ← 매 턴 출력되는 코드블록 구조
◇세계관     ← 배경, 세력, 시스템 뼈대
◇캐릭터     ← 기호 사전 + 1행 압축 테이블
```

### 2. 섹션 구분자 선택

마크다운 `#` 대신 특수문자를 쓰면 바이트를 절약하면서 시각 구분도 명확해짐.

| 용도 | 기호 | 예시 |
|---|---|---|
| 대분류 | `◇` | `◇규칙` |
| 중분류 | `§` | `§기사` |
| 소분류 | `¶` | `¶일과` |

단, `#` 마크다운도 AI 파싱에 문제없으므로 취향/플랫폼에 따라 선택. 핵심은 **계층이 일관되게 유지되는 것**.

### 3. 메인 프롬프트 vs 로어북 분리 기준

| 메인에 남기는 것 | 로어북으로 빼는 것 |
|---|---|
| 매 턴 참조해야 하는 골격 | 특정 조건에서만 필요한 상세 |
| 출력 형식, 상태창 구조, 이미지 공식 | 지역/유적/에피소드 상세 설정 |
| 기호 사전, 캐릭터 식별 테이블 (1행) | 캐릭터 서사, 과거, 관계 깊이 |
| 세계관 뼈대 (세력명, 구조, 등급 체계) | 모드별 행동 변화 상세 |
| 절대규칙, 금지사항 | NSFW 연출 디테일 |

**판단 기준**: "AI가 이 정보 없이 다음 턴을 올바르게 출력할 수 있는가?" → Yes면 로어북, No면 메인.

### 4. 로어북 트리거 설계

로어북은 키워드가 대화에 등장할 때만 활성화되도록 트리거를 설정.

```
로어북 제목 [트리거 키워드]
예: 로어북 3 [!음란모드,🔞]
예: 로어북 6 [블러드 더스트,차원의 원한]
```

이렇게 하면 **필요한 정보만 필요한 순간에 컨텍스트에 주입**되어 토큰 낭비를 방지.

## 구획 B — 압축 테크닉

---

### 1. 핵심 원칙: 글자를 빼는 게 아니라 밀도를 높이는 것

압축의 목표는 "같은 토큰 안에 더 많은 유효 지시를 담는 것". 불필요한 군더더기를 빼고 그 자리에 실질적 지시를 채우는 구조.

### 2. 극한 압축 문법

조사·띄어쓰기·접속사를 제거하고 기호로 관계를 표현.

| 기호 | 의미 | 예시 |
|---|---|---|
| `+` | 나열, 그리고 | `냉정+내유+염려` |
| `→` | 시간순, 인과 | `고백→전이→위장결별→연심잔존` |
| `=` | 정의, 동치 | `원거리무기멸시=비겁상징` |
| `/` | 또는, 병렬 | `자율적/능동적/진취적` |
| `()` | 보충 설명, AI 전용 내면 정보 | `(現도승훈에게 두려움)` |
| `&` | 병렬 연결 | `일상물&로맨스&판타지` |
| `外` / `內` | 밖/안, 겉/속 | `外냉정+內소심` |
| `禁` | 금지 | `임의생성禁` |
| `X` / `O` | 불가/가능 | `의존X`, `상세묘사O` |

### 3. 기호 사전 선언 → 이후 기호만 사용

반복되는 텍스트를 기호 하나로 치환. 상단에서 한 번 정의하면 이후 전체에서 재사용.

```
◈=발트하임제국 / ◎=용혈국 / ▣=마탑 / ❖=페리아법국
♡=존댓말 / ☆=반말
○=탄막 / ■=육체강화 / ◇=기동
```

**효과**: "발트하임제국"(6글자)이 캐릭터마다 반복 → `◈`(1글자). 캐릭터 20명이면 100글자 이상 절약.

### 4. 별칭 치환

긴 섹션명이나 반복 참조되는 용어에 짧은 별칭을 부여.

```
-{{user}}=U, 캐릭터=C
-상태창=KH
```

참조가 많을수록 절약 효과가 커짐. 단, **별칭이 너무 많으면 AI가 혼동**할 수 있으므로 핵심 용어에만 적용.

### 5. 설명형 문장 → 기능 압축형 전환

문장으로 풀어쓴 지시를 `키워드→결과` 패턴으로 재구성.

**Before (문장형):**
```
등장인물은 유저에게 의존하지 않고, 자율적이며 능동적이고 진취적으로 행동합니다.
```

**After (압축형):**
```
-등장인물:{{user}}의존X,자율적/능동적/진취적 행동
```

### 6. 압축 대상 vs 비대상

| 압축하는 영역 | 건드리지 않는 영역 |
|---|---|
| 규칙, 지침, 설명 | 이미 1행 압축된 캐릭터 데이터 |
| 세계관 서술 | 상태창 코드블록 구조 |
| 묘사 가이드, 톤 지시 | 이미지 출력 공식 (정확도 필수) |

**원칙**: 규칙/설명은 밀도를 높이고, 데이터/공식은 정확성을 위해 그대로 유지.

### 7. 마크다운 깊이 정리

헤더 단계가 깊어질수록 `#` 기호가 누적되어 바이트를 소모. `####`(4바이트) 수준까지 가면 정리가 필요.

**방법**: 깊은 헤더 대신 특수문자 구분자(`§`, `¶`)를 혼용하거나, 들여쓰기 없이 `-`로 계층을 표현.

## 구획 C — 캐릭터 테이블 & 상태창 설계

---

### 1. 캐릭터 1행 압축 테이블

캐릭터 한 명의 정보를 테이블 1행에 담는 것이 핵심. 메인 프롬프트에서 캐릭터가 차지하는 공간을 최소화하면서도 AI가 즉시 식별 가능하도록.

**컬럼 설계 순서**: 식별 → 외형 → 내면 → 능력 → 부가정보

```
名|코드|⚥|나이|소속|외형|성격|말투|예시말투|능력|등급|이명|특이사항
```

**실제 적용 예시:**
```
아린|A2|♀|23|◈|금발녹안+거유|평소=낯가림+소심,투구씀=능글+대담|평소=더듬는♡,투구씀=거친☆|죄,죄송해요|창술|SS|흑우|기아스=선제공격불가
```

**설계 원칙:**
- 컬럼 순서를 고정하고 모든 캐릭터가 동일 형식을 따름 → AI가 패턴을 학습해 파싱 정확도 상승
- 조건부 상태는 `평소=X,조건=Y` 형식으로 1셀 안에서 분기
- 서사·관계·과거 같은 깊이 정보는 로어북으로 분리하되, 서사 압축이 필요하면 화살표(`→`) 체인으로 처리: `고백→전이→위장결별→연심잔존`

### 2. 캐릭터 코드 체계

2글자 영문 코드를 부여해 이미지·상태창·참조에 재사용.

| 방식 | 예시 | 적합한 경우 |
|---|---|---|
| 이름 약자형 | `AL`(앨리스), `BL`(벨리트라) | 캐릭터명이 고유하고 약자 충돌 없을 때 |
| 소속+번호형 | `A1`(기사1), `B3`(무인3) | 소속별 분류가 중요할 때 |
| 역할코드형 | `a1`(진설), `b1`(리아) | 서사적 중요도 순서로 정렬할 때 |

**핵심**: 코드는 한 번 정의하면 프롬프트 전체(이미지 공식, 상태창, 로어북 참조)에서 통일 사용. 중복·충돌 없도록 사전에 설계.

### 3. 공용 설정 분리

캐릭터 전원에게 적용되는 규칙은 테이블 밖에서 한 번만 선언.

```
◇캐릭터 공용
-全캐릭=처녀
-캐릭간이명으로부름
-개별사고:유저와캐릭 비밀유지+내면공유X
-기본말투:무협풍 고풍스러운, 상세는 개별성격에 따름
```

이렇게 하면 개별 캐릭터 행마다 "처녀", "이명 사용" 등을 반복 기입할 필요가 사라짐.

### 4. 상태창 설계

상태창은 매 턴 출력되는 코드블록. AI가 현재 상태를 추적하는 대시보드 역할.

**구조 원칙:**

```
```STATUS
[모드 플래그]
[위치] [날짜] [시간]
[유저 기본정보]
[유저 능력/등급/소속]
[자원/인벤토리]
[파티/동행]
[캐릭터별 상태 행]
[일정]
```　
```

**캐릭터 상태 행 형식:**
```
[이름]:❤️n|소속|의복상태|현위치,상세행동
```

### 5. 이모지 플래그 = 상태 인디케이터

변수 선언 없이 이모지 하나로 상태를 표현. **선택지를 명시적으로 제한**해서 AI 혼동을 방지.

| 용도 | 이모지 세트 | 규칙 |
|---|---|---|
| 모드 표시 | `🔞`, `↔️`, `🍁` | 상태창 최상단에 삽입, 활성 모드만 표기 |
| 상황 표시 | `⚪`(평시) `🔴`(성행위) `🔵`(전투) | 3개만 사용, 상황 따라 자동 전환 |
| 의복 상태 | `👕`(착의) `🚫`(나체) | 2개만 사용 |
| 특수 구간 | `⬛`(평시) `⬜`(백야 진입중) | 2개만 사용 |

**핵심**: "N개 이모지만 사용"을 명시하는 것. 제한하지 않으면 AI가 임의 이모지를 생성함.

### 6. 호감도 체계

```
-호감도❤️:0~100[증오→혐오→불쾌→무관심→흥미→우정→호감→사랑]
-변동:U와대화→❤️+2, 실망/분노→❤️-1
-기본호감도:80(평범)
```

**설계 포인트:**
- 범위와 감정 라벨을 한 줄에 매핑
- 변동 규칙은 `트리거→변화량`으로 압축
- 캐릭터별 기본값이 다르면 캐릭터 테이블 특이사항란에 기입

## 구획 D — 이미지 시스템 & 모드 시스템

---

### 1. 이미지 출력 공식

이미지 URL을 `베이스URL + 캐릭터코드 + 상황넘버 + 확장자`로 조합하는 구조. AI가 상황만 판단하면 URL이 자동 결정됨.

**공식 선언:**
```
공식:![](https://도메인/경로/캐릭터코드/상황넘버.확장자)
```

**실제 예시:**
```
§메인캐릭
공식:![](https://itimg.kr/413/GN/메인캐릭코드/상황넘버.webp)
例
아린 경멸중=![](https://itimg.kr/413/GN/A2/3.webp)
```

**핵심**: `例`(예시)를 반드시 포함. AI는 공식만으로는 조합을 틀리는 경우가 있으므로 구체적 대입 예시가 정확도를 크게 올림.

### 2. 상황 넘버링 설계

번호 구간을 용도별로 분리해 충돌을 방지.

| 구간 | 용도 | 예시 |
|---|---|---|
| 0~44 | 공통 상황 (표정, 일상, 이벤트) | `0:첫등장` `9:분노` `31:결혼` |
| 45~77 | 성관계 (유저♂) | `63:정상위弱` `65:정상위射` |
| 110~114 | 성관계 (유저♀) | `113:정상위` |
| 200번대 | 전투 | `201:전투중` `203:부상` |

**하위 분류 인라인 압축:**
```
펠라(49:냄새맡는|50:시작|51:불알|52:딥스|53:射|54:보여줌|55:삼킴)
기승위(弱:60|强:61|射:62)
```

괄호 안에 `번호:설명`을 파이프로 나열하면 별도 행 없이 한 줄에 세부 분기를 담을 수 있음.

### 3. 이미지 카테고리 분리

캐릭터 외에 장소·단역도 별도 코드 체계를 가짐.

```
§장소코드
공식:![](https://도메인/경로/back/장소넘버.webp)

§단역코드
공식:![](https://도메인/경로/extra/단역넘버.webp)
```

**원칙**: 카테고리마다 공식을 독립 선언 + 각각 `例` 포함. AI가 카테고리를 혼동해 캐릭터 공식에 장소 넘버를 대입하는 실수를 방지.

### 4. 이미지 출력 규칙

공식과 별도로 "언제, 어떻게 출력하는가"를 명시.

```
-상황에 어울리는 다른종류이미지 개별출력
-실제등장중인 캐릭터만출력
-장소이미지=특정장소도착시 必 1회만출력
-미존재상황코드 임의창조禁
-서술&묘사단락 전 상단삽입
```

**특히 중요한 것**: `임의창조禁`. 이걸 명시하지 않으면 AI가 존재하지 않는 넘버를 만들어내는 경우가 빈번.

### 5. 모드 시스템

같은 캐릭터 세트의 초기값·관계·톤을 통째로 오버라이드하는 장치. 캐릭터를 재정의하지 않고 변수만 교체.

**모드 선언 구조:**
```
### 모드명
-특징: 변경되는 설정을 나열
-상태창 최상단에 모드이모지 추가
```

**실제 예시:**
```
### 역전모드
-특징:도승훈이 1년 뒤늦게 소환된 것으로 변경,
 강아린 초기호감도=❤️60🖤20, 진설 초기호감도=❤️60🖤50,
 U를 B급모험가로 변경, 도승훈을 F급으로 변경...
-매 INFO 최상단에 ↔️ 추가
```

**설계 포인트:**
- 모드가 변경하는 항목만 명시. 언급되지 않은 설정은 기본값 유지 (여백의 미)
- 상태창에 모드 이모지를 삽입해 AI가 매 턴 현재 모드를 확인
- 모드 활성화는 트리거 키워드(`!역전모드`)로 제어

### 6. 모드와 로어북의 연동

모드 상세는 로어북에 넣고, 트리거 키워드로 활성화.

```
로어북 4 [!역전모드,↔️]  ← 유저가 "!역전모드" 입력 시 활성화
로어북 5 [!정상화,🍁]    ← 유저가 "!정상화" 입력 시 활성화
```

메인 프롬프트에는 모드의 존재와 이모지만 기록해두고, 실제 변경 내용은 로어북이 담당. 메인 프롬프트를 가볍게 유지하는 구조.

## 다섯 번째 예시 분석: 모드 시스템 심화

**1. 모드 = 콘텐츠 전체의 라우팅 장치**

```
💬:대화,이동        → 기본 출력
🗡️:전투             → 전투시스템 로어북 + 전투 이미지 코드 + 대미지 계산식
📈:주식거래          → 주가 템플릿 + F&G 지수 + 거래창 출력
🍳:요리              → 요리 이미지 코드 + FOOD 코드블록 + 장사 시스템
🎰:카지노            → 게임 시스템 + 카지노 전용 규칙
👌/👙/🐰/✂️/🤌/💃: 성관계 세부 모드 → 각각 전용 상황코드 세트
```

**2. 모드 이모지 = 로어북 트리거와 동일**

모드 이모지가 곧 로어북 활성화 키워드. `🗡️`가 활성화되면 로어북 11(무장), 12(NPC스탯), 13(전투시스템)이 동시에 주입. **메인 프롬프트에는 모드 목록만 두고, 실제 규칙은 전부 로어북에 분산.**

**3. 상태창 상단의 모드 표시 = AI 자기 확인 장치**

```
🔧:n/🟠
```

매 턴 상태창 최상단에 현재 모드를 출력하게 함으로써 AI가 "지금 어떤 모드인가"를 매번 스스로 확인. 모드 전환 시 즉시 반영되어야 하므로 `💬→🐰` 같은 중간 표기를 금지하고 최종 모드만 표시.

**4. 자동변환 vs 지정변환의 분리**

```
자동변환: {{user}}행동/상황 → 🔧모드전환
복귀규칙: 모든특수모드종료 → 💬복귀
```

유저가 전투를 시작하면 자동으로 `🗡️`, 끝나면 자동으로 `💬`으로 복귀. 유저가 명시적으로 전환할 필요 없이 **상황 기반으로 AI가 판단**. 단, 특수 모드(📈, 🎰 등)는 유저의 명시적 행동이 트리거.

**5. 모드별 전용 출력 템플릿**

각 모드가 고유한 코드블록 양식을 가짐.

```
전투: ```전투출력``` (대미지 계산식)
거래: ```DEAL``` (품목, 가격)
요리: ```FOOD``` (요리명, 등급, 설명)
주식: 🗠₿ 테이블 (종목, 가격, 변동률)
```

이렇게 하면 AI가 모드에 따라 "어떤 형식으로 출력해야 하는지"를 명확히 구분.

**6. 로어북 세분화 전략**

성관계 이미지 코드만 해도 로어북 2~8로 분산. 이유는 **에덴 플랫폼의 로어북 토큰 한계** 때문. 하나의 로어북에 모든 상황코드를 넣으면 토큰 초과로 잘릴 수 있으므로, 트리거가 같더라도 내용량에 따라 물리적으로 분할.

**7. 커스텀/랜덤 시작 = 모드의 확장 개념**

```
{커스텀모드:{내용}} → 기본초기상황 무시, 유저 입력 내용을 초기상황으로 반영
{랜덤스타트} → AI가 세계관 기반으로 흥미로운 시작 생성
```

이건 "게임 모드"가 아니라 **시작 조건 오버라이드**. 모드 시스템의 개념을 초기 설정까지 확장한 패턴.
