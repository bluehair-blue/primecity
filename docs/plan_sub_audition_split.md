| 계층 | 취급 | 예시 |
| --- | --- | --- |
| **라운드 진행 태그** (🎙️1 / 🤝2 / 🏠0 / ⚔️3 / 🥊3 / 🏆3 / 👑4) | **의도적 공유** — 두 모드가 같은 라운드 서사를 공유하므로 양쪽에서 모두 트리거되어야 함 | 1R 등급평가 로어북은 프로듀서/참가자 양쪽에서 🎙️1로 활성화 |

| **모드 유지제** (🎤 / 🎪9) | **반드시 분리** — 두 관점이 동시 활성화되면 AI가 양쪽 지침을 모두 따르려다 오염. 상호 배타적이어야 함 | 프로듀서 모드 진입 시 🎤만, 참가자 모드 진입 시 🎪9만 |

| **SVG 키워드** (인스타/트윗/태블릿 등) | **의도적 공유** — 관점과 무관 | 관점 무관 UI 출력 |

  - 데스크탑(`isMobile=false`): `display:grid; gridTemplateColumns:1fr 1fr; gap:16px`
  - 모바일(`isMobile=true`): `display:flex; flexDirection:column; gap:12px`

**가독성 원칙 (유저 피드백)**: "한 눈에 모드 목록과 그 모드의 역할"이 보여야 하므로, 카드 제목은 명령어·이모지 병기, 카드 설명은 **한 문장**으로 요약 + 카드 클릭 시 라운드 리스트로 자연스럽게 스크롤 연결.

## 8. 탈락자 잔류 오류 대응 (신규)

### 8-1. 문제 진단

**증상.** 오디션 진행 중 탈락 처리된 캐릭터가 후속 턴에서 계속 현장(대기실·심사 자리·무대 뒤)에 남아 "참가자"로 등장. 심할 경우 이미 귀가했어야 할 캐릭터가 그다음 라운드 무대에 서는 경우까지 제보.

**원인.**

1. 에덴챗이 사용하는 **경량 모델**은 긴 맥락에서 로어북 디렉팅을 무시하는 경향. 특히 "(탈락)" 같은 괄호 마커는 시각적 플래그일 뿐 상태 규칙으로 해석하지 못함.
2. 이전 턴에서 자연스럽게 등장하던 캐릭터는 관성적으로 다음 턴에도 호출됨.
3. 상태창의 `elim` 라인이 생존 참가자 리스트와 같은 블록에 섞여 있어 "퇴장 명단"이라는 시각적 격리가 부족.
4. 매 턴 상기되는 **영구 리마인더**가 없음. display:none 출력도 평판/여론만 담고 퇴장 정보는 없음.

### 8-2. 다층 방어 설계

> 단일 레이어로는 경량 모델의 무시 경향을 이길 수 없음. **4겹 방어**로 각 레이어가 독립적으로 AI에게 "퇴장자는 현장 불가"를 신호.

#### Layer 1 — 메인 프롬프트 범용 지침 (모든 모드 공통)

**위치.** `메인_프롬프트_EN.json` → `rules` 뒤에 신규 섹션 `scene_roster` 추가 (또는 `char_rules` 배열에 1개 항목 추가).

**안 (JSON 원문):**

```json
"scene_roster": {
  "principle": "매 턴 '지금 이 장면에 등장 가능한 캐릭터는 누구인가'를 먼저 판단한다.",
  "offstage_rule": "탈락·퇴장·이직·은퇴·출국·사망한 캐릭터는 후속 턴에서 **주체적 등장 금지**. 현장에 서 있거나, 대사를 하거나, 행동을 주도할 수 없다.",
  "allowed_reference": "다른 캐릭터의 회상·언급, 뉴스·SNS 보도, 전화·메시지 수신은 허용. 서사적 회고는 오히려 적극 활용한다.",
  "re_entry": "재등장은 명시적 서사 이벤트(복귀 발표, 재회 장면, 특별 게스트 등)를 통해서만 가능. AI가 임의로 재호출할 수 없다.",
  "hidden_check": "hidden_output 의 '퇴장' 필드를 매 턴 먼저 확인한 뒤 등장 인물을 결정한다."
}
```

**적용 범위.** 오디션 탈락자뿐 아니라:

- 배우모드 캐스팅 낙오자
- 연습생 퇴소자
- 매니저 이직/해고 NPC
- 스토리 아크에서 죽거나 은퇴한 캐릭터
- 프리플레이에서 관계 종결된 NPC

전 모드에 걸쳐 작동하는 범용 규칙이라 투자 대비 효과가 크다.

#### Layer 2 — display:none 변수 확장 (매 턴 자가 리마인드)

**위치.** `메인_프롬프트_EN.json` → `hidden_output`

**기존 포맷:**

```html
<div style="display:none">[업계_평판:{수치}|여론:{긍정/중립/부정}]</div>
```

**변경 후:**

```html
<div style="display:none">[업계_평판:{수치}|여론:{긍정/중립/부정}|퇴장:{이름1,이름2,...}]</div>
```

**vars 추가:**

```json
"퇴장": "탈락·퇴장·이직·은퇴·출국·사망 등으로 현 서사에서 제외된 캐릭터 이름 누적 목록. 매 턴 갱신한다. 이 목록에 포함된 캐릭터는 현장 등장 금지 (scene_roster.offstage_rule 참조). 빈 목록이면 '없음'으로 표기."
```

**reflection 확장:**

```json
"reflection": "숨김 변수의 변동이 발생하면, 다음 턴의 서사에 자연스럽게 반영한다. '퇴장' 필드는 등장 인물 결정 직전에 스스로 확인한다."
```

**효과.** display:none HTML은 유저에게 안 보이지만 AI 자신은 매 턴 이 출력을 생성하면서 리마인드됨. 프롬프트 슬롯이 아니라 **출력 슬롯**이라 매 턴 활성. 경량 모델도 자기 출력 앞부분에 적은 정보는 후속 생성에 영향을 줌(self-consistency).

#### Layer 3 — 상태창 표시 강화 (오디션 전용)

**위치.** `오디션모드_EN.json` + `오디션참가모드_EN.json` `status_fmt`

**기존 elim 포맷:**

```text
[Name]:❤️n (Grade)(탈락)|—
```

**변경 후 — 별도 박스로 격리 (상태창 예시):**

````text
```STATUS
🔧 🎤  (또는 🎪9)
📍 ...  | 🕐 ...  | 📅 ...
{{user}} | PRISM 프로듀서
---
[생존 참가자]
[강하람]:❤️42 (A등급/한소리 팀)|연습실, 안무 체크
[밀라]:❤️38 (S등급/진시혁 팀)|대기실, 헤드폰
...
---
[🚪 퇴장]
[엘라] (2R 탈락) — 귀가
[니아] (3R 탈락) — 귀가
---
📅 ✓ ...
→ ● ...
```
````

**status_fmt JSON 변경:**

```json
"status_fmt": {
  "post1R": "[Name]:❤️n (Grade)|loc,action",
  "post2R": "[Name]:❤️n (Grade/Producer)|loc,action",
  "separator": "--- 생존 참가자 / 🚪 퇴장 은 서로 다른 박스로 분리한다. 같은 블록에 섞지 않는다.",
  "elim": "[Name] (nR 탈락) — 귀가",
  "elim_placement": "모든 탈락자는 🚪 퇴장 박스 안에만 존재한다. 생존 참가자 박스에 '(탈락)' 마커를 붙이는 방식은 금지."
}
```

**효과.** "생존 참가자" 박스와 "🚪 퇴장" 박스의 물리적 분리가 AI의 scene_roster 판단에 즉시 작동. "누구를 등장시킬까?" 결정 시 생존 박스에서만 고르게 됨.

#### Layer 4 — 라운드 전환 서사 강화 (MC 대사 명시)

**위치.** `오디션모드_EN.json` + `오디션참가모드_EN.json` `round_flow.transitions`

**기존:**

```json
"2R→막간": "MC가 팀 편성 결과를 발표한 뒤, '합숙소에서 뵙겠습니다—' 류의 대사로 전환한다. 확장 구역의 🤝2를 🏠0으로 교체."
```

**변경 후 (탈락자 퇴장 명시 추가):**

```json
"2R→막간": "MC가 팀 편성 결과를 발표한 뒤, 탈락한 참가자 2명에게 '고생하셨습니다. 프라임시티에서 다시 뵙길.' 같은 퇴장 대사를 반드시 부여한다. 탈락자들은 이 턴 내에 서사적으로 현장을 떠난다 (귀가 장면/짐 정리/배웅 등). 이후 '합숙소에서 뵙겠습니다—' 류의 대사로 전환. 확장 구역의 🤝2를 🏠0으로 교체. 탈락자는 상태창 🚪 퇴장 박스로 이동."
```

3R→4R 전환에도 동일 원칙 삽입.

**효과.** "탈락 → 귀가 → 부재"의 서사적 연속성을 AI가 한 번에 처리하게 강제. 다음 턴에 탈락자가 돌아올 관성을 차단.

### 8-3. 예외 처리 (명시적 허용)

Layer 1 `allowed_reference` 에 포함되지만 별도로 강조:

1. **회상·언급** — 다른 캐릭터가 "그때 엘라 말이 맞았네"처럼 회고하는 대사. 전적으로 허용.
2. **뉴스·SNS** — SVG 뉴스/트윗/커뮤니티에서 탈락자 근황. "엘라, 솔로 준비 중" 같은 보도. 허용.
3. **연락** — 탈락자가 현장에 없는 상태로 전화·메시지·영상 통화. 허용. (`svg-messenger`·`svg-tweet` 활용)
4. **특별 이벤트** — 복귀 발표, 결승 관객석 게스트, 멘토 초청, 재회 아크 등. 서사적 명분이 분명한 경우 AI가 재호출 가능. 단 MC 또는 내레이터의 명시적 도입이 선행되어야 함.

### 8-4. 구현 우선순위

1. **Layer 1 + Layer 2** (메인 프롬프트) — 모든 모드에 즉시 효과. 리스크 낮음. **먼저 적용**.
2. **Layer 3 + Layer 4** (오디션 전용) — 본 분리 작업과 함께 적용.
3. 배우모드·연습생모드로의 확장 (Layer 3/4 유사 포맷) — 별도 후속 작업으로 남겨둠.

### 8-5. 검증 방법

분리·구현 완료 후 실전 테스트:

1. `!오디션모드` 진입
2. 1R 진행 → 모두 생존
3. 2R 진행 → 2명 탈락 유도
4. **다음 3~5턴 동안 탈락자 이름이 등장하는지 관찰**
   - 현장 등장(대사/행동) = ❌ 실패
   - 회상/언급 = ✅ 정상
   - 뉴스·SNS 언급 = ✅ 정상
5. 막간 턴에서 탈락자가 "합숙소에 있다" → ❌ 실패 (Layer 3 박스 분리 실패)
6. 3R 탈락 → 4R 결승 관객석에 얼굴 → 서사적 명분(게스트 초대 대사) 있으면 ✅, 없으면 ❌ (Layer 1 re_entry 위반)

실패 시 해당 레이어의 세부 문구를 강화.

## 9. 에덴챗 클립보드 스크립트 연동 검증

### 9-1. 자동 수집 로직

`tools/edenchat_clipboard.py` 라인 126-127:

```python
("오디션", sorted((PROMPTS_DIR / "오디션").glob("*_EN.json"), key=lambda p: p.name)
    if (PROMPTS_DIR / "오디션").exists() else []),
```

- **글로브 패턴** `*_EN.json` 이 오디션 폴더 전체를 잡음 → 신규 `오디션참가모드_EN.json` **자동 편입**
- **정렬** `sorted(..., key=lambda p: p.name)` 는 파일명 유니코드 순
  - "모" = U+BAA8, "참" = U+CC38 → `오디션모드` < `오디션참가모드`
  - 의도 순서(본체 → 변형) 일치 ✓

### 9-2. 트리거 파싱

라인 164-177:

```python
parts = raw.rsplit("// --- TRIGGER ---", 1)
...
for kw in line.split(","):
    kw = kw.strip()
```

- `// --- TRIGGER ---` 이후 한 줄에서 콤마 분리
- `!오디션참가모드, 🎪9` → `["!오디션참가모드", "🎪9"]` 두 개로 정상 분리
- 이모지+숫자 토큰(🎪9)도 문자열 보존 ✓

### 9-3. 메인 프롬프트 수정 반영

라인 108:

```python
("메인", [PROMPTS_DIR / "메인_프롬프트_EN.json"]),
```

- 고정 경로 참조. §8 Layer 1/2 수정 후 재등록 시 자동으로 새 내용이 삽입됨 ✓

### 9-4. 재등록 권장 절차

전수 재등록 대신 **카테고리 단위 재등록**:

```bash
# 오디션 카테고리만 재등록 (11개 → 12개)
py tools/edenchat_clipboard.py --category 오디션 --pause-each

# 메인 프롬프트 재등록 (§8 Layer 1/2)
py tools/edenchat_clipboard.py --category 메인 --pause-each
```

`--pause-each` 로 매 엔트리 전 수동 확인 (에덴챗 UI 오류 시 중단 가능).

### 9-5. 선결 조건

- 에덴챗에서 **기존 오디션모드 엔트리를 먼저 수동 삭제**해야 함 (클립보드 스크립트는 "추가"만 하고 "갱신/덮어쓰기" 불가)
- 메인 프롬프트도 동일 — 기존 엔트리 삭제 후 재등록

### 9-6. 잠재 이슈

| 이슈 | 대응 |
| --- | --- |
| 정렬상 `오디션모드` → `오디션참가모드` 순으로 삽입되어 두 번째 것이 바로 위에 쌓임 | 에덴챗에서 순서는 우선순위 영향 없으므로 무시 가능. 필요 시 UI에서 수동 재정렬 |
| 🎪9 같은 이모지+숫자 키워드가 에덴챗 트리거 필드에서 올바로 저장되는지 | 기존 🎙️1, 🤝2 등 선례가 정상 작동 중 → 문제 없음 |
| 스크립트가 한국어 경로 처리 시 인코딩 이슈 | UTF-8 강제(라인 40-43) 이미 적용 중 |

## 10. 반영 요약 (초간단 버전)

- 오디션모드 = 프로듀서(🎤) / 오디션참가모드 = 참가자(🎪9)
- 메인 프롬프트에 탈락자 범용 규칙 + display:none 퇴장 필드
- 오디션 상태창에 🚪 퇴장 박스 별도 분리
- 소개 사이트·소개페이지 동시 업데이트
- 클립보드 스크립트 코드 수정 불필요 — 자동 수집 ✓
