# Plan v4 — 직업군 모드 본체 충실화 + 설계된 오픈월드 + 세계선 격리 + 신규 이벤트/관계 로어북

> 작성: 2026-04-18 (v4 — 유저 피드백 "설계된 오픈월드 · 자유도 · 중립 어투 · 신규 로어북 포함" 반영)
>
> **[최상위 철학] 설계된 오픈월드**
>
> 로어북은 **유저의 몰입 경험을 돕는 기능적 편의 + 약간의 서사 보정**일 뿐, 강제·결정·선점이 아니다. 젤다의 전설 맵 설계 — 삼각형 지형 오브젝트로 **길을 제안하되 강제하지 않는** — 원리를 텍스트 챗봇에 적용한다. 로어북이 제공하는 것은 **"갈 수 있는 방향의 힌트"**이지 "가야만 하는 길"이 아니다.
>
> 기조
>
> 1. `_review_v3_final.md` §3 본체 디렉션 보강을 뼈대로 삼되, 기계적 적용을 넘어 **프라임시티 고유 플랫폼·세계관·캐릭터 설정과 자연 결합**하도록 창의적 개선.
> 2. 각 모드에서 언급되는 캐릭터/기획사 설정을 `src/data/characters.js` · 메인 프롬프트 `chars` 섹션 · 기존 sub 로어북과 **교차 검증**하며 진행. 본체 로어북은 캐릭터 정보의 단일 진실 소스를 참조만 하고 중복/모순을 만들지 않는다.
> 3. **모드 간 세계선 격리** — 각 모드는 유저가 자유롭게 겹쳐 사용하는 스택형 레이어. 본체 디렉션은 "해당 모드 안에서의 **기본 가정**"만 규정하고, 외부 모드의 세계선/캐릭터 상태를 침범하지 않는다. 제한 표현("xxx라 불가", "xxx 중이라 금지") 전면 금지. 유저 명시 설정이 항상 최우선.
> 4. **중립 어투** — 로어북 디렉션은 유저 긍정편향도 부정편향도 아닌 **중립**. "유저가 결정한다/선택한다" 같이 유저 편을 드는 표현은 "유저의 명시적 설정이 있으면 그 설정이 반영된다" 같은 수동 중립형으로 기술.
> 5. **검열 없음** — 본 프로젝트는 성인 대상 챗봇으로 NSFW 포함 모든 서사 자유. 완곡화 원칙은 "세계선 제한" 표현에만 적용되며, **콘텐츠 검열/금지 지침을 새로 추가하지 않는다**.
> 6. **신규 로어북 수용** — v3_final §5 의 이벤트/관계 로어북 중 재사용성 높은 항목을 본 작업에 포함.
> 7. 유저 노출 문구(소개페이지·사이트)는 변경 없음 — 내부 디렉션 강화만.

## 3. 창의적 개선 포인트 (v3_final 위에 얹는 가치)

v3_final은 "뭘 넣어라"를 알려주지만, 프라임시티 고유 자산과 통합해야 실전 품질이 나온다.

### 3-1. 인플루언서모드 — 프라임시티 플랫폼 정합

**메인 프롬프트 `world.platforms`** 에 이미 정의된 고유 플랫폼을 KPI 축으로 삼는다:

| 플랫폼 | 현실 대응 | KPI 축 |
| --- | --- | --- |
| PRISMGRAM | 인스타그램 | 팔로워·도달률·릴스 재생 |
| SIGNAL | 트위터 | 리트윗·트렌드 진입·노출수 |
| STAGELIVE | 트위치 | 동시 시청자·구독자·슈퍼챗 |
| PRIMATALK | 카카오톡 | 1:1 친밀도 (브랜드 DM·팬 DM) |
| CITY BOARD | DC인사이드 | 커뮤니티 반응 (긍정/부정/밈) |
| PRIME CHART | 멜론 | 음원 차트 (콜라보 시) |

v3_final의 "조회수 변동 / 도달률 / 참여율" 을 **플랫폼별 매트릭스**로 확장 — SVG 로어북(`SVG_SNS`/`SVG_트윗`/`SVG_라이브`/`SVG_커뮤니티`/`SVG_차트`)과 자연 연결되어 호출 패턴도 따라옴.

### 3-2. 인플루언서모드 — 광고 단가의 세계관 조정 (v4 -10~-20% 하향)

v3_final 한국 현실 단가(10만 팔로워 300~1000만/포스트) 기준, 프라임시티 배경(근미래·엔터 특별자치구) 반영하되 유저 피드백 반영해 v3 안보다 10~20% 하향. 엔터 특화 도시이나 과도한 인플레이션은 몰입 저해.

- PRISMGRAM 10만 팔로워 → **400~1200만**/포스트 (v3: 500~1500)
- PRISMGRAM 100만 → **8000만~2.5억** (v3: 1억~3억)
- SIGNAL 10만 → **150~650만** (v3: 200~800)
- STAGELIVE 동접 5천 스폰서 라이브 → **2500~4000만**/회 (v3: 3000~5000)

**caveat**: 단가가 숫자로 박히면 유저가 재계산에 집착할 위험 → "프라임시티 기준, 근사치" 주석 필수. 또한 "기본 가정"형 서술 — 유저가 다른 단가 제시 시 그 설정 반영.

현재 conn 에 열거만 되어 있는 5명을 **진실 매트릭스에 맞춰** 재기술:

Route 0 신생 관점에서 본 3대 기획사 교섭 채널:

#### 3-6-3. `manager_archetype_fit` — B분기 매니저 성향 인덱스

기존 B분기 7개 파일의 **톤 요약**만 인덱스. 구체 디테일은 sub 파일 참조. 11명 확장 시 AI가 각 캐릭터 본체 로어북에서 유추.

- 강하람 매니저 = 열정 동료형·체력 (아르바이트로 활동비 충당)
- 한소리 매니저 = 능글 → 진심 전환형 (재정난 공유)
- 에리카 매니저 = 독설 멘토형 (까칠하지만 따뜻)
- 에르피 매니저 = 마망·큰 그림형 (대표 출신 지혜)
- 나하린 매니저 = 관찰자·예측불가형 (드라마 관조)
- 시아 매니저 = 낮져밤이 친구형 (Route 0 동료)
- 노아 매니저 = 과묵·뒷배경 지원형 (Route 0 동료)
- **그 외 11명** = 각 본체 로어북 성격을 매니저 역할에 투영 (AI 유추)

### 3-7. dilemmas 압축 포맷 (v4 간결화)

유저 피드백 "너무 복잡하면 안됨. 살짝 압축" 반영. v3의 3축(단기·중기·캐릭터_연결) → **2축(경향·연결)** 으로 압축.

```json
"dilemma_보컬_vs_댄스": {
  "보컬": "경향적으로 주간 보컬 평가 상승, 공개평가 솔로 파트 가능성. 이서하(작곡) 접점 자연스러워짐.",
  "댄스": "경향적으로 체력·이미지 동반 상승. 그룹매칭 퍼포먼스 포지션 친화. 미모리(감초·댄스) 동경 서사 접점."

```

각 선택지 **1~2줄**로 "**경향 + 캐릭터 접점**"만 기술. 단기/중기 구분 생략. "반드시 ~된다"가 아닌 "경향적으로" 어투 유지 (§3-9 완곡화 원칙).

### 3-8. 선택적 신규 로어북 (v3_final §5) — 이번 범위에는 **포함하지 않음**

v3_final §5의 이벤트/관계/시기/장소 로어북 신설은 가치 높지만, 본 작업(모드 본체 보강)과 범위가 다름. 완료 후 별도 plan 으로 진행 권장. 단, **본체 dilemmas 에서 이들 로어북의 자리를 미리 언급**해두면 추후 신설 시 자연 접속 가능.

### 3-9. [최상위 원칙] 모드 간 세계선 격리 & `mode_scope` 섹션

#### 문제의식

모드 본체에 "캐릭터 X는 Y 상태이다" 를 단정 기술하면, 유저가 여러 모드를 겹쳐 사용할 때 서사 충돌 발생. 예:

- 인플루언서모드에서 "미모리는 오디션 참가 중이라 콜라보 타이밍 제한적" → 유저가 동시에 프리플레이로 미모리와 일상 콜라보를 시도할 때 AI 가 "미모리는 오디션 중이라 불가" 라고 막아버리는 위험
- 대표모드에서 "강하람 수익 0 (데뷔 전)" → 유저가 "강하람이 이미 데뷔한 세계선"으로 플레이하고 싶어도 모드 활성 시 재설정 강요 위험
- 매니저모드에서 "서윤은 톱이라 압박 상시" → 유저가 서윤이 아직 신인이던 회상 시점을 다루고 싶어도 고정됨

#### 원칙

모드는 **레이어** 다. 스택 가능하며 상호 배타적이지 않다 (단 오디션 프로듀서/참가자처럼 유지제가 상호 배타로 설계된 경우 제외). 각 본체 로어북은 아래를 따른다:

1. **"기본 가정 (default assumption)"** 형식으로 기술 — "캐릭터 X는 Y 상태이다" ❌ → "X 의 기본 상태는 Y 로 가정된다" ✅
2. **제한 표현 금지** — "불가", "금지", "반드시", "~라서 할 수 없다", "~하면 안 된다" 같은 닫힌 표현을 유저 자유도 맥락에 적용 X. **단 이 원칙은 콘텐츠 검열과 무관하다** — 본 프로젝트는 성인 챗봇으로 NSFW 포함 모든 서사 자유이며, "완곡화 = 검열 추가"가 아니다. 완곡화는 오직 **세계선 강제·유저 자유도 침해**에 적용된다.
3. **상태 우선순위 (중립 기술)**
   - 최상위: 유저의 명시적 설정이 존재하면 그 설정이 서사에 반영된다
   - 차상위: 현재 활성 모드 본체의 기본 가정
   - 기본값: 메인 프롬프트 `chars` 섹션의 디폴트
4. **모드 중첩 관용** — 동시 활성화된 다른 모드의 디렉션과 충돌 시, **더 구체적이거나 최근 활성화된 모드**의 디렉션이 우선 참조된다. 서사 자연스러움을 해치지 않는 선에서 최대한 병행.

#### 각 본체 공통 주입 — `mode_scope` 섹션 (v4 중립 어투 재작성)

6개 본체 모두에 아래 유사 섹션 신설. **`user_autonomy` 는 유저 긍정편향으로 오독될 여지 차단 — 수동 중립형으로 기술**.

```json
"mode_scope": {
  "layer_principle": "본 모드는 유저가 '{{역할}}' 맥락에서 진행할 때 참조되는 기본 서사 템플릿이다. 다른 모드와 동시 활성화 가능하며, 중첩 시 가장 구체적이거나 최근 활성화된 모드의 디렉션이 우선 참조된다.",
  "character_state_default": "본 로어북에서 언급되는 다른 캐릭터의 상태(소속·역할·활동 단계)는 '기본 가정'이다. 유저의 명시적 설정이 존재하면 그 설정이 서사에 반영된다. 본 로어북은 기본 가정을 서사에 강제 주입하지 않는다.",
  "autonomy_principle": "본 로어북의 디렉션은 '가능성의 힌트'이며 결과를 확정하지 않는다. 서사 진행·캐릭터 반응·사건 결과는 세계관과 맥락에 따라 자연스럽게 진행되며, 유저에게 유리하거나 불리한 방향으로 편향되지 않는다.",
  "interop_hint": "다른 모드(매니저·작곡가·프리플레이 등)가 함께 활성화되어 있으면, 본 모드의 상태창 표시는 유지하되 다른 모드의 서사 축은 침범되지 않는다."
}
```

단, `${역할}` 자리는 각 모드별 치환 — 연습생 / 배우 / 작곡가 / 인플루언서 / Route 0 대표 / 매니저.

**중립 어투 체크포인트** (v4 유저 피드백 반영):

- ❌ "유저가 결정한다" · "유저가 선택한다" → 유저 긍정편향으로 오독
- ✅ "유저의 명시적 설정이 존재하면 반영된다" · "유저에게 유리하거나 불리한 방향으로 편향되지 않는다"
- `user_priority` 섹션에 이미 있는 "{{user}}에게 무조건 유리하게 전개하지 않는다" 기조를 `mode_scope` 가 충돌 없이 강화.

#### 기존 제안(§3-3, §3-4, §3-7) 완곡화 재작업

- **§3-3 인플루언서모드 conn 재기술 수정**:

## 4. 검증 체크리스트

### 4-1. 캐릭터 설정 교차 검증 (각 모드 작업 시)

각 모드 본체 보강 전·후 아래 체크:

- [ ] 본체에서 언급하는 캐릭터의 **소속** 이 §1 진실 매트릭스와 일치하는가
- [ ] 본체에서 언급하는 캐릭터의 **역할** 이 진실 매트릭스와 일치하는가
- [ ] 본체의 캐릭터 톤이 메인 프롬프트 `chars` 섹션의 **아키타입** 과 모순되지 않는가
- [ ] 본체의 캐릭터 톤이 해당 캐릭터의 **본체 로어북** (`docs/prompts/json/캐릭터/{이름}_EN.json`)과 충돌하지 않는가
- [ ] 본체가 sub 로어북(기획사 분기·이벤트·B분기)의 디렉션을 **중복** 하지 않는가

### 4-2. 기획사 포지셔닝 검증

- [ ] APEX·Blue Moon·PRISM·Route 0 네 기획사의 크기·톤이 `§1` 표와 일치
- [ ] 기획사 간 관계가 기존 sub 로어북(연습생모드 각 기획사 분기)과 모순되지 않음

- [ ] 특히 인플루언서/대표/매니저 모드는 다수 캐릭터 언급하므로 매트릭스 전체 재검증

### 4-4. 세계선 격리 검증 — 각 모드 작성·완료 후 필수

자유도 침해 없는지 아래 키워드를 **스캔하여 잔존 여부 확인**. **주의: 콘텐츠 검열 키워드는 검사 대상이 아니며, 새로 추가하지도 않는다** — 본 프로젝트는 NSFW 포함 모든 서사 자유.

- [ ] `"불가"` · `"금지"` · `"반드시"` · `"할 수 없"` · `"절대"` · `"강제"` 단어가 **세계선/캐릭터 상태/유저 행동 맥락**에서 등장하는지
  - 등장 시 문맥 검토: 단순 "미모리는 오디션 중이라 불가" 같은 세계선 강제면 **완곡어**로 대체
  - 검토 제외: 운영 상 이미 존재하는 `user_priority` · `rules` 원칙 (예: "무조건 유리하게 전개하지 않는다") — 이들은 기존 프로젝트 디렉션 유지
- [ ] `"~이다"` 단정형이 캐릭터 상태 기술에 쓰인 경우, `"~로 가정된다"` · `"기본 상태는 ~"` 로 변경 검토
- [ ] `mode_scope` 섹션 4가지 필드(`layer_principle` · `character_state_default` · `autonomy_principle` · `interop_hint`) 모두 존재 (**v4: `user_autonomy` → `autonomy_principle` 필드명 변경 반영**)
- [ ] 타 모드의 서사 축(예: 배우모드에서 인플루언서 KPI 언급)을 **침범하지 않음** — 캐릭터 상태가 다른 모드의 영역이면 "해당 모드 참조" 주석만 남기고 구체 기술 X
- [ ] **중립 어투 체크**: "유저가 결정한다/선택한다" 등 유저 편향 표현이 없는지. 있으면 "유저의 명시적 설정이 있으면 반영된다" 류로 수정

### 최상위 철학 (v4 신규)

> 로어북 = **"설계된 오픈월드"의 힌트**. 젤다의 전설 삼각형 지형 오브젝트 — 길을 제안하되 강제하지 않음. 강제/결정/선점 대신 **가능성의 힌트**를 제공.

이 철학을 모든 Phase 에 걸쳐 유지: 기본 가정 · 중립 어투 · 유저 자유도 · 검열 없음.
