## 파일 유형별 분석

### 1. 영문화 JSON (최종 산출물, 에덴챗 삽입용)

챗봇 로어북의 최종 형태. 원본 한국어 → 영문화 → 압축의 과정을 거침.

| 파일 | 엔트리 수 | 크기 | 트리거 |
|---|---|---|---|
| 메인 프롬프트 | 1 (상시) | 8.4KB | 항상 활성 |
| 캐릭터 로어북 | 14 | 22.9KB | 캐릭터 이름 (진시혁, 에리카, ...) |
| 오디션 로어북 | 8 | 6.8KB | !오디션모드, 🎙️1~👑4, !오디션참가 |
| 나하린 로어북 | 1 | 3.7KB | 나하린 (🔒스포일러 보호) |
| 세계관 이면 | 1 | 2.5KB | 🌑세계관 (나하린 L2+ 후 활성) |
| 모드 로어북 | 7 | 11.4KB | !매니저모드, !연습생모드, ..., !선택지 |

**구조적 특징:**
- 키 축약 (`user_dynamics`→`ud`, `relationships`→`rel`, `호감도_initial`→`fav`)
- 화살표 표기 (`→`, `↔`)
- 한국어 고유명사 유지 (고데레, 짠꿉공, 후배님 등)
- !오디션참가는 오디션 로어북 id:0의 `perspective` 필드로 통합

### 2. 한국어 로어북 원본 (작업 기반)

영문화 전 원본. Phase 1(캐릭터), Phase 4(모드)에서 생성.

- **로어북_캐릭터/**: 16파일 (14캐릭터 + 🔒나하린 + 🔒세계관_이면), 총 932줄
  - 장그루가 가장 복잡 (86줄, Layer1/Layer2 이중 구조)
  - 🔒나하린이 가장 김 (115줄, 4층위 스포일러)
- **로어북_모드/**: 8파일, 총 699줄
  - 오디션_오프닝이 가장 김 (170줄, Beat 1~7 시퀀스)
  - 매니저/오디션참가가 각 102줄 (분기 구조)

### 3. NAI 프리셋

이미지 생성 자동화(tools/asset_generator.py)의 원본 데이터.

| 프리셋 | 장면 수 | 내용 |
|---|---|---|
| 감정 | 8 | angry, contempt, happy, sad, shy, smirk, surprised, troubled |
| 일상 | 9 | normal-chat ~ pregnant |
| 상황(NSFW) | 41 | cunnilingus ~ pregnant-after-sex |
| 착의 | 16 | clothed 체위 변형 |
| **합계** | **74** | 캐릭터당 74장 × 15명 = 1,110장 |

### 4. NAI 백업 (748KB)

`nais2-backup-2026-03-22.json` — NovelAI 에셋 에디터의 전체 백업.
15명 캐릭터의 clothed/nude 프롬프트, 장면별 Female/Male Part 프롬프트가 포함.
`tools/extract_config.py`로 이 백업에서 `asset_config.json`을 추출함.

### 5. 작업 계획서

**CLI_에이전트_작업_지시문.txt** — 프로젝트 전체 로드맵:
- Phase 1: 캐릭터별 로어북 (한국어)
- Phase 2: 영문화 + 포맷 최적화
- Phase 3: SVG 커스텀 도메인
- Phase 4: 직업군 모드 + 오디션 보조 모드
- Phase 5: 프롬프트 품질 개선 (미완)

**마크다운 프롬프트 작성 가이드라인.txt** — AI 프롬프트 설계 원칙:
- 배치 순서 = 우선순위 계층
- 구획별 역할 정의 (절대규칙, 규칙, 출력지침, 이미지규칙, 상태창, 세계관)

### 6. 은랑밀입국/ (별도 프로젝트)

프라임시티와 무관한 별도 챗봇 프로젝트(은랑/Silver Wolf from Honkai: Star Rail).
포맷 실험용으로 보임 — 동일 프롬프트를 XML, YAML, 압축 등 다양한 형태로 변환하여 비교.

### 2-A. 전체적 구조 비교

| 요소 | Source (한국어 txt) | JSON (영문) | 평가 |
|---|---|---|---|

| 대화 패턴 | 상황별 2~3개 예시 + 한국어 원문 | `voice` 객체 상황별 2개 | 🟢 예시 수는 비슷, 영문화 자체는 적절 |
| 호감도 변동 | 상승/하락 **구체적 상황 + 대사 예시** | `ud.i/d/u/hi` 1줄씩 | 🔴 **약어 불분명 + 구체성 상실** |
| 관계 역학 | 상대별 3~5줄 관계 설명 | `rel` 객체 각 1줄 | 🟡 방향성은 유지, 역동성 약화 |
| 트리거 지뢰 | 에리카: `"너를 위해서야"/"잘 될 거야"/"재능만 있으면 되지"` | 없음 | 🔴 **핵심 감정 트리거 누락** |
| 탈락 반응 | 3~5줄 상세 묘사 | `elim` 1~2줄 | 🟡 톤은 전달되나 디테일 부족 |

### 2-B. 캐릭터별 핵심 누락

**진시혁**:
- Source: "유저를 처음 봤을 때: 감정으로 프로듀싱하는 놈 → 경멸에 가까운 관심" — JSON의 `ud.i`는 "Contemptuous curiosity"로 축약. 톤은 유지되나 **AI가 초기 충돌을 어떻게 연출해야 하는지** 부족.
- Source: "분기: 거부→대립 / 수긍→동맹, 함께 업계를 뒤흔듦" — JSON의 `ud.hi`는 "Alliance" 한 줄. **분기 후 서사적 비전** 누락.

**에리카**:
- 🔴 Source의 **트리거 지뢰 3개** ("너를 위해서야" / "잘 될 거야" / "재능만 있으면 되지") 완전 누락.
- Source: "아티스트가 끝까지 에리카를 원망하지 않았다는 게 가장 큰 상처" — JSON은 "Artist never blamed her — deepest wound"로 축약했지만, **이것이 에리카의 모든 행동을 관통하는 핵심**이라는 무게가 부족.
- Source: "에리카가 고른 구체적 선택지가 결과적으로 사고로 이어짐 (잘못된 선택)" — 단계적 실패 과정(3단계)이 JSON에서 한 덩어리로 합쳐짐.

**장그루**:
- Source Layer 2의 **분기 구조 테이블** (감정폭발, 짝사랑 인지, 탈락 위기 각각 2갈래) — JSON `L2`에 `reunion` 3단계만 기술, 분기 테이블 누락.
- Source: "호칭 변화: '프로듀서님'(선 그음) → 감정 격해지면 옛날 호칭 누출. 본인이 제일 당황" — JSON `speech` 한 줄로 요약. **호칭 전환이 만드는 드라마** 미전달.

**한소리**:
- Source: "'후배님' = 한소리만의 것" — JSON은 "'후배님' = exclusive nickname"으로 축약. ✅ 핵심 유지됨.
- Source: "장부에 '이번달도 완벽하게 적자~!!' 메모. 필체는 밝지만 숫자는 빨간색" — JSON `ledger` 유지 ✅.
- Source: "전 유저가 프로듀서로서 짊어질 무게의 원점" — **메타 역할 정의** 누락.

**서윤**:
- 🔴 Characters 문서: "본명은 따로 있음. 원래는 작곡과 그림이 꿈이었으나, 나하린에 의해 무대로 방향 전환 (본인은 자연스럽게 끌렸다고 생각)" — JSON `inner`에 "Original dream: composing+art"로 간략 언급하나, **"본인은 모른다"는 핵심 비극이 약함**.
- Characters 문서: "좋아하는 것/싫어하는 것" 리스트 — JSON 미반영. AI가 서윤의 호불호를 판단할 근거 부재.

### 2-C. `ud` 키 약어 문제

현재 JSON 약어:
```
"ud": { "i": ..., "d": ..., "u": ..., "hi": ... }
```
AI에게 `i`=initial, `d`=down, `u`=up, `hi`=high의 의미가 불분명.
Source에서는 "초기 태도", "호감도 하락 시", "호감도 상승 시", "최상위 호감도"로 명확하게 라벨링.

**개선 방향**: `initial`, `down`, `up`, `peak` 또는 `first_impression`, `disappoint`, `impress`, `deep_bond` 등 자기설명적 키로 교체.

## 6. 종합: AI 자율성 vs 사용자 의도 균형 분석

### 현재 JSON의 자율성 스펙트럼

```
[제한적] ◀━━━━━━━━━━━━━━━━━━━━━━▶ [자율적]
         ┃                                   ┃
   절대규칙 5개              서사 전개 방향
   이미지 코드 DB            감정 변화 속도
   상태창 포맷               이벤트 선택
                             관계 진행 속도
```

### 문제점

1. **감정 변화 속도 가드레일 없음**: Source는 "한 턴 만에 적대→호감, 냉담→연정 급변 금지"를 명시. JSON에 없어서 AI가 캐릭터를 갑자기 풀어버릴 위험.

2. **서사 주도권 경계 모호**: Source는 "라운드 전환은 유저 확인 후"를 명시. JSON은 자동 전환을 허용하여 유저가 중요한 순간을 놓칠 수 있음.

3. **"안 되는 것"이 불명확**: Source의 `<Prohibitions>` 6항 → JSON `absolute_rules` 5항. 특히 "메타 발언 금지", "숨김변수 노출 금지"가 빠짐.

4. **캐릭터별 DO/DON'T 부재**: Source에는 캐릭터마다 "이 캐릭터는 이런 상황에서 절대 이렇게 행동하지 않는다"가 함축되어 있으나, JSON에 명시적 `forbidden_behaviors`가 없음.

### 핵심 개선 방향

| 영역 | 방향 | 구체적 실행 |
|---|---|---|
| 자율성 확보 | AI가 서사를 주도할 수 있는 **명확한 범위** 선언 | `autonomy` 필드: 이벤트 생성, NPC 자율 행동, 분위기 전환 허용 범위 |
| 의도 보존 | **감정 변화 속도 제한** + **라운드 전환 확인** 복원 | `guardrails` 필드: 급변 금지, 메타 금지, 전환 확인 |
| 캐릭터성 강화 | **트리거 단어**, **금지 행동**, **호감도 역학** 상세화 | 캐릭터별 `triggers`, `forbidden`, `fav_dynamics` 필드 |
| 가독성 개선 | `ud.i/d/u/hi` → 자기설명적 키 | 키 이름 변경 + 각 상황별 1~2줄 구체화 |
| 누락 복원 | Hidden Tracker, 응답 길이, 내면 독백 규칙 | 메인 프롬프트 JSON에 `hidden_tracker`, `length_guide`, `monologue_rule` 추가 |
