## 🔴 분리 가능 (UX 영향 적음)

### 1. **`user_priority` 필드 — 거의 모든 모드에 동일 (29파일 중 27파일)**
- 텍스트가 글자 그대로 동일: "{{user}}가 자신의 소속·배경·역할 등 세계관 설정을... (이하 동일 200자)"
- **27 × 200 = 5,400자가 완전 중복**
- **메인 프롬프트에 `user_priority` 글로벌 룰로 1번만 정의** → 약 5,000자 절약 (거의 메인 프롬프트 1개 분량)

### 2. **`maintain` 필드 — 정형화 (모든 직업군 모드)**
- "상태창 🔧란에 X를 유지한다." 패턴 동일
- 메인 프롬프트의 `status.mode` 룰에 통합 가능

### 3. **매니저 B분기 7파일 — 구조 100% 동일**
- 각 파일 = title + user_priority + priority + style + loop_override (AM/Day/PM/Night) + voice + conn_override
- 차이는 캐릭터별 voice 5줄과 style/loop 묘사
- **현재 평균 1,500자 × 7 = 10,500자**
- **압축 전략**: 공통 구조(매니저B 메타 룰)를 별도 로어북으로 분리하고, 각 매니저B 파일은 캐릭터별 voice + 한 줄 스타일 요약만 → 평균 600자 × 7 = 4,200자 (절약 6,000자+)

## 🟡 모드 로어북 구체화 권장

### 1. **연습생모드** — 가장 부족
- exp 필드만 있고 events/dilemma/외부 자극이 없음
- 단순 훈련 루프 → 매주 평가 → 데뷔. 구체적 분기 부족
- **추가 권장**:
  - events: 공개 평가 / 그룹 매칭 / 부상 / 멘토링 / 퇴소 압박
  - dilemma: 보컬 vs 댄스 집중 / 그룹 vs 솔로 노선 / 한소리 vs 다른 기획사
  - relations 확장: 다른 연습생들 (현재 강하람만 강조)

### 2. **배우모드** — events 부재
- loop은 있으나 매니저모드처럼 events 카테고리가 없음
- **추가 권장**: cast 종류(드라마/영화/단막), 후반작업(더빙/홍보), 갈등(감독/공연주), 스캔들 종류

### 3. **작곡가모드** — 미발표곡 아크 부족
- "이서하의 미발표곡 아크"가 conn에 잠깐 언급되지만 구체적 분기 없음
- **추가 권장**: 작곡 워크플로 (영감 → 데모 → 편곡 → 매칭) 단계화

### 4. **인플루언서모드** — events는 있으나 실제 콘텐츠 결과 시뮬레이션 약함
- "AI가 시장 반응 시뮬레이션" 명시되어 있지만 구체적 KPI 가이드 없음
- **추가 권장**: 조회수/도달/참여율 변동 가이드라인, 광고 단가 표

### 5. **대표모드** — 자금 시스템 약함
- exp에 "자금: ₩n" 있지만 단가/예산/지출 구조 없음
- **추가 권장**: 운영비(월세/연습생 식비/마케팅) 분기, 수익원(광고/공연/캐스팅 수수료)

### 6. **소꿉친구모드** — branches가 너무 추상적
- "eruption_accepted/rejected", "knew_feelings/didnt_know" 분기는 있지만 구체적 시나리오 부족
- 장그루_재회 로어북과 일부 정보 중복 (재회 후 분기는 소꿉친구모드, 재회 자체는 _재회)
- **분리 명확화 또는 통합** 검토

### 7. **매니저모드 본체** — events 풀이 좋지만 캐릭터별 적용 가이드 부족
- "broadcast/schedule/scandal/fan/brand/crisis" 6종 events
- 각 events가 어떤 캐릭터와 가장 잘 맞는지(예: scandal × 엘라, fan × 미모리) 가이드 없음

## 🔴 차라리 빼는 것이 모드 명확성에 도움

### 1. **매니저B 7파일의 voice 카테고리 비율**
- 한소리/에리카/시아/노아/강하람은 본체에 풍부한 voice 있음
- 매니저B의 voice 5줄은 본체 voice의 압축 변형
- → **매니저B의 voice 제거 + "본체 voice를 매니저 톤으로 사용" 룰**로 대체 가능

### 2. **모드 본체의 loop 단계가 너무 정형적**
- 모든 모드가 AM/Day/PM/Night 4단계
- 실제로는 캐릭터/이벤트가 시간 흐름을 바꿈 → AI가 4단계 강박을 가질 수 있음
- → **시간 단계를 가이드 라벨로 격하** (필수 → 선택)

### 3. **conn 필드의 카메오 캐릭터들**
- 매니저모드 conn에 9명, 작곡가모드 conn에 5명 등
- 모든 캐릭터를 다 등장시키려는 의도지만 모드 핵심에서 분산
- → **핵심 3~4명만 명시, 나머지는 "다른 캐릭터도 자연스럽게 등장 가능"**
