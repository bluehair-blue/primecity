## 설계 원칙

| 원칙 | 설명 |
|---|---|
| **로어북 = 디렉팅 툴** | AI는 "적당히"를 모른다. 로어북이 그 "적당히"를 가르치는 유일한 수단 |
| **키워드 = 상태창 형식 기반** | AI의 최종 출력 형식을 면밀히 분석하여 트리거를 설계. 캐릭터명 직접 사용 지양 → 상태창 포맷(`이름: ❤️숫자`) 또는 상황 단어 활용 |
| **기폭제 + 유지제** | 모드 로어북은 1회성 기폭 키워드(`!명령`) + 상태창 이모지 유지 키워드를 반드시 쌍으로 구비 |
| **긍정형 유도** | "~하지 마라" 대신 "~처럼 묘사한다". "A가 아니라 B다" 패턴도 지양 → "B처럼 묘사한다"로 직접 유도 |
| **완전 몰입** | 제4의 벽은 존재하지 않는다. 메타 용어(`ai_direction`, `AI는`) 사용 금지 |
| **로드맵 ≠ 매턴 지침** | 장기 서사 시퀀스는 별도 로어북으로 분리. 본체에 두면 AI가 매턴 재활용 |
| **점진적 변화** | 캐릭터는 서사가 쌓이면 변한다. 호감도 기반으로 행동 가이드가 유동적으로 전환 |
| **언어 선택** | 세계관과 캐릭터의 매력을 가장 살리는 언어로 통일. JSON 포맷은 고정 |

## 트리거 키워드 설계 원칙

에덴챗의 트리거 시스템은 **AI 출력 텍스트에 키워드가 포함되면 해당 로어북이 활성화**되는 구조.
따라서 키워드 설계 시 AI의 최종 출력 형식을 정밀하게 고려해야 한다.

### 상태창 형식 활용

현재 상태창:
```
[서윤]: ❤️15 | 더 코어, 연습실에서 홀로 노래하고 있다
```

활용 가능한 키워드 패턴:
- `서윤]: ❤️1` → 호감도 10~19 범위에서 활성 (10,11,...,19 모두 매칭)
- `서윤]: ❤️2` → 호감도 20~29
- `서윤]: ❤️` → 서윤이 상태창에 존재하기만 하면 활성 (주의: 항상 활성됨)

### 경우의 수 확대 원칙

- 분리 로어북 트리거에 **캐릭터 본명을 단독으로 쓰지 않는다** (본체 로어북과 중복 활성)
- 대신 **상태창 포맷 조합** 또는 **상황에서 나올 법한 단어 조합**을 사용
- 여러 키워드를 등록하여 하나라도 매칭되면 활성화되도록 그물을 넓힌다

### 모드 기폭제 + 유지제 패턴

```
기폭제 키워드: !매니저모드          ← 유저가 1회 입력
유지제 키워드: 📋                   ← 상태창에 모드 이모지가 박혀 있는 한 매턴 활성
로어북 내부 지침: "상태창 🔧란에 📋를 유지한다."
```

모든 모드 로어북에 이 패턴을 적용.

## 언어 선택 판단

### 판단 기준
- 에덴챗은 **한국어 챗봇**. 유저 입력도 한국어, AI 출력도 한국어.
- 로어북은 AI가 읽는 지침. AI가 한국어를 출력하기 위해 **영문 지침을 읽는 것**은 토큰 효율적.
- 그러나 **대사 예시, 고유명사, 감정 뉘앙스**는 한국어 원문이 맥락을 더 정확히 전달.

### 결론 (제안)
- **지침/구조**: 영문 (토큰 효율 + AI 파싱 정확도)
- **대사 예시, 고유명사, 감정 표현**: 한국어 원문 유지
- **키 이름**: 영문 (JSON 가독성)
- 현재 혼용 구조를 그대로 유지하되, 대사 예시의 한국어 비중을 늘린다.
