# 프라임시티 챗봇 — CLI 에이전트 단계별 작업 지시문

## 전제
- 에덴챗(Eden Chat) 플랫폼용 한국어 롤플레이 챗봇
- 마감: 2026년 4월 5일
- 모든 작업물은 한국어로 먼저 작성 → Phase 2에서 영문화
- 토큰 효율성 항상 염두. 극단 압축보다 가독성 우선.
- 캐릭터 프로필 원본: `캐릭터_프로필.txt`, 세계관 원본: `세계관.txt`
- 메인 프롬프트: `연예계_챗봇_메인_프롬프트.txt`
- 오디션 로어북: `연예계_챗봇_로어북__오디션_.txt`

# Phase 1: 캐릭터별 로어북 프롬프트 작성

## 원칙
- 메인 프롬프트의 1행 압축 테이블은 "요약 참조용". 로어북은 AI가 해당 캐릭터를 **깊이 있게 연기**하기 위한 상세 지침.
- 메인 프롬프트와 중복되는 외형/직업 등은 로어북에 재기술하지 않음. 메인 프롬프트에 없는 정보만 추가.
- 스포일러/유저 경험 강제 배제: "이 캐릭터는 나중에 X를 한다" 같은 서사 결과를 직접 명시하지 않음. 대신 동기/성향/트리거를 기술하여 AI가 자연스럽게 도출하도록 유도.
- 나하린은 별도 구역(Phase 1-B)으로 분리. 스포일러 등급이 가장 높음.
- 각 로어북의 트리거 키워드는 캐릭터 이름(한글).

## Phase 1-A: 일반 캐릭터 로어북 (나하린 제외)

### Step 1-A-1: 심사위원 3인 (진시혁, 에리카, 이서하)
- 원본: `캐릭터_프로필.txt`의 해당 캐릭터 섹션
- 작성할 내용 (캐릭터당):
  1. **내면 상세**: 메인 프롬프트에 없는 과거, 동기, 내적 갈등
  2. **대화 패턴**: 말투 샘플 3~5개. 상황별(평상시/긴장/감정적) 톤 변화
  3. **{{user}}와의 관계 역학**: 초기 태도, 호감도 변동에 따른 태도 변화 방향
  4. **다른 캐릭터와의 관계**: 주요 관계선 2~3개
  5. **호감도 초기값**: 오디션 모드 기준
- 이서하는 오디션 미등장이지만, 에리카와의 관계가 에리카 로어북에서 참조되므로 함께 작성
- 포맷: 마크다운. `# 캐릭터명` → `## 내면` → `## 대화 패턴` → `## 관계` → `## 호감도`

### Step 1-A-2: PRISM Studio (한소리, 강하람)
- 한소리: 유저의 출발점. 오디션 시작 전 오프닝 대화의 톤/감정선이 중요
- 강하람: 오디션 미등장이지만 유저의 동료로서 향후 서사에 관여
- 작성 항목은 Step 1-A-1과 동일

### Step 1-A-3: 오디션 참가자 8인 (장그루~라피스)
- 원본: `캐릭터_프로필.txt` + `오디션.txt`의 참가자 슬롯
- 장그루는 레이어 1(독립) + 레이어 2(소꿉친구 모듈) 구분하여 작성
- 작성할 내용 (캐릭터당):
  1. **오디션 성향**: 슬롯 역할(재도전/실력파/성장형 등)에 맞는 행동 패턴
  2. **무대 스타일**: 1R에서 보여줄 퍼포먼스 성향 (AI 묘사 가이드)
  3. **대화 패턴**: 말투 샘플 2~3개
  4. **{{user}}와의 관계 역학**: 호감도 변동에 따른 반응
  5. **탈락 시 반응**: 감정적 톤과 대사 방향
  6. **호감도 초기값**: 오디션 모드 기준
- 포맷: 마크다운. 동일 구조.
- 8명을 한 번에 하지 말고, 4명씩 나누어 작성 (토큰 초과 방지)
  - Batch A: 장그루, 밀라, 엘라, 니아
  - Batch B: 하시은, 라피스, 레이, 미모리

### Step 1-A-4: 서윤
- 오디션 잠깐 등장 예정. 로어북은 간략하게.
- 향후 메인 서사 히로인이므로 확장 여지를 남기되, 현재는 최소 정보만.
- 작성 항목: 내면 상세, 대화 패턴, {{user}}와의 접점 힌트, 호감도 초기값

## Phase 1-B: 나하린 전용 로어북 (스포일러 구역)

### Step 1-B-1: 나하린 4층위 로어북
- 원본: `캐릭터_프로필.txt`의 나하린 섹션 (서사적 층위 표 포함)
- **별도 로어북으로 분리하는 이유**: 나하린의 흑막 설정은 유저가 발견해야 할 정보. 다른 캐릭터 로어북에 혼입되면 AI가 조기 노출할 위험.
- 작성할 내용:
  1. **층위별 행동 지침**: 1층(멘토) → 2층(흑막 인지) → 3층(파멸 욕구) → 4층(R-19)
  2. **층위 전환 트리거**: 어떤 조건에서 다음 층위로 넘어가는지
  3. **대화 패턴**: 층위별 말투 변화
  4. **{{user}}와의 관계**: 층위별 태도 변화
  5. **절대 금지사항**: "AI가 나하린의 흑막 정체를 유저가 발견하기 전에 암시/노출하지 않을 것"
- 트리거 키워드: 나하린의 이름 + 별도 플래그(예: 🌑나하린)
- 포맷: 마크다운. 층위별 섹션 분리.

### Step 1-B-2: 세계관 이면 로어북
- 원본: `세계관.txt`의 "🔒 나하린 루트 참고용" 섹션
- 프라임시티의 설계자로서의 나하린, 구조적 레일, 복선 가이드
- 이 로어북은 나하린 층위 2+ 진입 후에만 활성화되는 구조
- 트리거 키워드: 별도 플래그(예: 🌑세계관)

# Phase 2: 프롬프트 영문화 + 포맷 최적화

## 원칙
- 한국어 → 영문 변환. 의미 보존 우선, 직역 금지.
- 포맷: JSON 기반. XML 대비 토큰 40~60% 절감.
- 구조: 각 로어북을 하나의 JSON 객체로. 에덴챗의 로어북 입력 형식에 맞춤.

## Step 2-1: 메인 프롬프트 영문화
- `연예계_챗봇_메인_프롬프트.txt` → 영문 JSON
- 섹션별로 나누어 변환 (절대규칙, 규칙, 출력지침, 상태창, 이미지, 세계관, 캐릭터)
- 기호 사전(⚙, ∮, ∂ 등)은 그대로 유지
- 캐릭터코드(SY, NHR 등)는 그대로 유지

## Step 2-2: 오디션 로어북 영문화
- `연예계_챗봇_로어북__오디션_.txt` → 영문 JSON × 8개 (로어북 0~7)
- 이모지 트리거(🎙️1, 🤝2 등)는 그대로 유지

## Step 2-3: 캐릭터 로어북 영문화
- Phase 1 산출물 전체 → 영문 JSON
- 캐릭터당 1 JSON 파일

## Step 2-4: 토큰 카운트 및 최적화
- 각 파일의 토큰 수를 측정 (tiktoken 또는 유사 도구)
- 에덴챗 토큰 한도 확인 후, 초과 시 추가 압축
- 압축 우선순위: 예시 제거 > 부연 축약 > 동의어 통일

## Phase 2 산출물
- 영문 JSON 파일 세트 (메인 프롬프트 + 로어북 전체)

# Phase 3: Cloudflare Workers SVG 커스텀 도메인 설정

## 현황
- 6개 SVG Workers 배포 완료 (*.odeye3217.workers.dev)
- bluehair.blue 도메인 Cloudflare 관리 중
- 커스텀 도메인 미등록 → 챗봇에서 URL 호출 시 정상 출력 불가

## Step 3-1: 도메인 매핑 계획
```
svg-community → community.bluehair.blue
svg-chart     → chart.bluehair.blue
svg-news      → news.bluehair.blue
svg-talk      → talk.bluehair.blue
svg-live      → live.bluehair.blue
svg-twit      → twit.bluehair.blue
svg-insta     → insta.bluehair.blue
```

## Step 3-2: Cloudflare 대시보드 설정 (Workers당 반복)
1. Workers & Pages → 해당 Worker 선택
2. Settings → Triggers → Custom Domains
3. `{subdomain}.bluehair.blue` 추가
4. DNS 자동 등록 확인 (AAAA 레코드)
5. 배포 테스트: `curl https://{subdomain}.bluehair.blue` → SVG 응답 확인

## Step 3-3: 메인 프롬프트 내 SVG URL 업데이트
- 기존 workers.dev URL → bluehair.blue 서브도메인으로 교체
- 이미지 출력 규칙과 별도로, SVG 출력 규칙 섹션에 반영

## Step 3-4: CORS 및 보안 확인
- 에덴챗에서 SVG를 정상 로드하는지 테스트
- 필요시 Workers 코드에 CORS 헤더 추가

## Phase 3 산출물
- 7개 커스텀 도메인 활성화
- 메인 프롬프트 내 URL 업데이트

# Phase 4: 추가 모드 로어북 작성

## Step 4-1: 오디션 보조 모드

### 4-1-A: !오디션참가 모드
- 유저가 프로듀서가 아닌 **참가자**로 오디션에 참여하는 모드
- 시점 전환: 심사석 → 무대 위
- 로어북 구조: 기존 오디션 로어북과 병렬. 같은 라운드 구조이되 유저 역할이 다름
- 심사위원(진시혁, 에리카)이 유저를 심사하는 구조
- 한소리가 관객석/백스테이지에서 응원

### 4-1-B: !선택지 모드 (서브 모드)
- 자유 텍스트 입력이 부담스러운 유저를 위한 보조 모드
- 매 턴마다 상태창에 2~3개 행동 선택지를 제시
- 유저는 번호 입력 또는 자유 입력 병용 가능
- 로어북 구조: 기존 모드 위에 덮어씌우는 애드온 형태
- 트리거: !선택지 (토글 ON/OFF)

### 4-1-C: 오디션 시작 상황 (오프닝 시퀀스)
- 기존 오디션 로어북 0에 추가하거나 별도 로어북으로 분리
- 한소리와의 사무실 대화 → 태블릿 핸드오프 → !오디션모드 진입
- 웹툰 콘티(`웹툰_텍스트_콘티.txt`)의 컷 6~16을 텍스트 시퀀스로 변환
- 유저 이름 첫 입력 트리거: 한소리가 "이름이 뭐였더라~?" → 유저 입력 → 이후 {{user}}로 호칭

## Step 4-2: 매니저 모드

### 4-2-A: !매니저 모드 설계
- 두 가지 분기:
  - **유저가 매니저**: 특정 캐릭터(서윤, 강하람 등)의 전속 매니저로 활동
  - **캐릭터가 매니저**: 유저가 아티스트, NPC 중 하나를 매니저로 고용
- 핵심 게임플레이: 스케줄 관리, 위기 대응, 관계 관리
- 상태창 확장 구역: [스케줄], [컨디션], [평판]
- 시작 상황: 기획사에서 매니저 배정 통보 → 담당 아티스트와 첫 대면

### 4-2-B: 매니저 모드 로어북
- 로어북 구조: 오디션 모드와 유사한 자기유지 루프
- 트리거: !매니저모드
- 이벤트 풀: 스케줄 관리, 방송 출연, 스캔들 대응, 팬미팅, 광고 촬영 등
- 각 이벤트의 성공/실패가 아티스트 컨디션과 평판에 영향

## Step 4-3: 기타 직업군 모드 (간략 설계)

### 4-3-A: 모드 후보 리스트
- !연습생모드: Route 0 소속. 강하람과 동료. 데뷔를 향한 성장 서사
- !작곡가모드: Blue Moon 또는 프리랜서. 이서하와 접점. 곡 제작 중심
- !배우모드: 드라마/영화 캐스팅 → 촬영 → 시사회. 서윤과 접점
- !인플루언서모드: 하입 로드 중심. SNS 팔로워 관리, 바이럴, 브랜드 딜

### 4-3-B: 각 모드별 간략 로어북
- 오디션만큼 디테일하지 않아도 됨
- 최소 구성: 시작 상황 시나리오 + 핵심 게임플레이 루프 + 상태창 확장 구역 양식
- 각 모드 1페이지 분량

## Step 4-4: 소개 사이트(intro.bluehair.blue) 반영
- 모드 목록과 시작 명령어를 소개 사이트에 추가
- 각 모드의 한 줄 설명 + 시작 방법
- React 컴포넌트로 모드 선택 카드 UI 구현

# Phase 5: 개선 아이디어 및 후속 작업

## 5-1: 프롬프트 품질 개선
- **AI 자가 점검 지시**: 매 5턴마다 상태창 정합성을 내부 검증하는 지시 추가
- **감정 잔여 시스템**: 직전 턴의 감정 톤을 다음 턴에 명시적으로 캐리오버하는 메커니즘
- **복선 스케줄러**: 세계관 이면 복선을 n턴에 1회 자동 삽입하는 규칙 (나하린 루트 준비)

## 5-2: 컨텐츠 확장
- **엔딩 분기 시스템**: 오디션 결과에 따른 후일담 3~5가지 (성공/부분 성공/실패/히든)
- **관계도 SVG**: 캐릭터 간 관계를 실시간으로 시각화하는 SVG Worker
- **계절 이벤트**: 크리스마스, 연말 시상식 등 시즌 한정 이벤트 로어북

## 5-3: 기술적 개선
- **이미지 프리로드**: 에덴챗에서 이미지 로딩 지연 최소화를 위한 CDN 캐시 설정
- **로어북 동적 로딩 테스트**: 에덴챗에서 다수 로어북 동시 활성 시 성능 테스트
- **상태창 코드블록 렌더링 테스트**: 에덴챗에서 이모지 트리거가 코드블록 내에서 정상 매칭되는지 확인

## 5-4: UX 개선
- **튜토리얼 모드**: 첫 플레이 유저를 위한 가이드 모드. 시스템 설명을 서사에 자연스럽게 녹임
- **세이브/로드 힌트**: 에덴챗의 대화 저장 기능을 활용한 체크포인트 안내
- **난이도 조절**: !이지 / !하드 토글. 이지=AI가 유저에게 유리한 판정, 하드=엄격 판정

# 실행 우선순위

| 순위 | Phase | 이유 |
|---|---|---|
| 1 | Phase 1 (캐릭터 로어북) | 챗봇 품질의 핵심. 없으면 캐릭터가 얕음 |
| 2 | Phase 4-1 (오디션 보조 모드) | 유저 경험 완성도. 오프닝 시퀀스 필수 |
| 3 | Phase 3 (SVG 도메인) | SVG가 작동해야 연출이 살아남 |
| 4 | Phase 2 (영문화) | 토큰 절감. 마감 직전 가능 |
| 5 | Phase 4-2~3 (추가 모드) | 확장 컨텐츠. 마감 후에도 가능 |
| 6 | Phase 5 (개선) | 런칭 후 반복 개선 |

# 주의사항
- 각 Phase는 독립적으로 실행 가능하지만, Phase 1 → Phase 2 순서는 반드시 지킬 것
- Phase 3은 Cloudflare 대시보드 접근이 필요하므로 사용자 확인 필요
- 모든 산출물은 `/home/claude/` 에서 작업 후 `/mnt/user-data/outputs/`로 복사
- 대화 중 결정이 필요한 사항은 반드시 사용자에게 확인 후 진행
