## 🟡 메인_프롬프트_EN.json (5,750자)

### 토큰 효율화 가능 (충분히 가능)
- **`absolute_rules` (5조항)**: `char_rules`와 일부 중복. `등장인물 자율성 + 감정 점진성 + 유저 개입 여지` 라는 요지가 양쪽에 있음. **하나로 통합 가능 → 약 200자 절약**
- **`narration` 5필드**: style/base/emotion/tension/monologue/multi_char. 6필드 모두 작가가 알아서 할 영역. AI에게 동시 명시 시 오히려 혼란. **monologue, multi_char 만 남기고 압축 가능 → 약 300자 절약**
- **`hidden_output`**: `<div style="display:none">` 시도. 에덴챗에서 실제로 숨김 처리 되는지 의문 — 보통 노출됨. **검증 후 제거 고려**
- **`img.examples` 11개**: 5~6개로 줄여도 모델이 패턴 학습 가능. **약 400자 절약**
- **`img.disambiguation` 6항목**: 너무 세세함. 핵심 3개(50 vs 51, 87~89 직전, 사후 구분)만 남기면 절약 가능

### 분리 가능 (UX 영향 적음)
- **`img` 섹션 전체 (1,500자+)**: 이미지 출력 전용 로어북으로 분리 → 메인 프롬프트 항상 활성, img 로어북은 캐릭터 등장 시 트리거. 이미지 시스템이 무거우니 분리하면 항상 로딩될 토큰 절약.
- **`status.schedule_line`**: SVG_일정표와 일부 기능 중복 (일정 표시). 메인에서 빼고 SVG_일정표에 통합 → 메인 200자 절약

### 구체화 권장
- **`out.ratio`**: "대사 4~8회, 묘사 2~3문단" — 너무 광범위. 모드별로 다르게 조정 권장 (오디션 모드 vs 일상)
- **`status.시간`**: "대화 1회당 +2분" — 행동 유형별 가이드라인이 부족 (식사=30분, 이동=15분 등)

### 평가
- **토큰 효율화 잠재력 大**: 1500~2000자 절약 가능 (현재 5,750자 → 4,000자 가능)
- **이미지 시스템 분리**가 가장 큰 효과

## 🟡 나하린 4파일 분리 (총 5,500자)

### 현재 분리: 본체 / 냉각 / 분기 / 심리

### 분리해도 UX 영향 적은 부분
- **`나하린_심리_EN.json`의 `black_choker`**: "이 의미는 서사에서 직접 언급되지 않는다" — 직접 언급되지 않을 거면 굳이 로어북에 넣을 필요? **삭제 가능**

### 분기/냉각 통합 검토
- `나하린_냉각`은 호감도 1~3 트리거 (낮을 때)
- `나하린_분기`는 호감도 7~9 트리거 (높을 때)
- 두 파일이 같이 활성될 일 없음 → **통합 가능** (조건부 분기로 묘사)
- 단, **분리 유지 추천**: 토큰 효율은 좋으나 LLM이 분기 처리 헷갈릴 수 있음

### 본체와 심리 통합
- `나하린_EN.json`의 `layers.2`(설계자 인지) 뒤로 `심리`의 origin/core_paradox가 사실상 동일 정보
- **나하린_심리는 본체 layers.3에 통합 가능** → 1파일로 압축 (단, 트리거 분리 손실)

### 평가
- 분리 자체는 정교한데, 정보 일부 중복
- 흑막 시스템은 가장 잘 짠 부분. 유지 권장

## 🟡 SVG 10파일 (총 9,000자+)

### 공통 구조 (10파일 동일)
- `context_check`: 1줄
- `platform`, `worker_domain`: 2줄
- `url_rules`: 5필드 (space/comma/question/forbidden/char_codes) — **10파일 전부 동일**
- `prompt`: 라벨 설명 + 출력 위치 + 양식 + 예시

### 분리해도 UX 영향 적은 부분 (큰 절약 기회)
- **`url_rules` 5필드가 10파일 전부 동일** — 메인 프롬프트나 별도 `SVG_공통_규칙` 로어북으로 1번만 정의
- 각 SVG 로어북에서 `url_rules` 제거 → **파일당 약 200자 × 10 = 2,000자 절약**
- 단, 에덴챗 로어북은 트리거 기반 활성이라 항상 함께 로드되는 게 아니므로 신중

### 모드/SVG 구체화 권장 (Phase 1에서 SVG 부분만)
- **SVG_라이브**: chat 메시지가 3개로 고정. 시청자 수에 따라 chat 수 조정 가이드 가능 (1만 시청자 = 격렬, 100명 = 한가)
- **SVG_차트**: 5위까지만. 캐릭터 곡이 6위 이하일 때 표시 방법 가이드 부재
- **SVG_뉴스**: ticker(스크롤 자막) 활용 예시 부족. 본 헤드라인과 ticker 연결 패턴 설명 필요
- **SVG_커뮤니티 vs SVG_게시글**: 두 SVG의 차이 명확하지만, 언제 둘 다 출력하는지(목록 → 클릭 시퀀스) 가이드 추가 가능
- **SVG_태블릿**: 오디션 오프닝 Beat 7에서만 출력 명시. 너무 좁음. 라운드 진행 중에도 사용 가능한 시점 추가 가이드 필요
- **SVG_메신저**: msg/reply 각 2개씩 고정. 더 긴 대화 시 어떻게 하는지 가이드 부재

### 토큰 효율화
- 각 SVG 파일의 `prompt` 섹션 끝 【URL 규칙】은 url_rules와 중복 — 제거 가능 (각 파일 100자)
- `prompt` 섹션의 【출력 위치】는 context_check와 일부 중복
